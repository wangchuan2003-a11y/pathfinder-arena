# 实现参考：加权寻路与可操作的地图

查阅日期：2026-09-07。通过 Jina Reader 读取以下四个一手页面的正文；未依据搜索摘要作结论。Red Blob Games 用于算法说明，W3C 的 Understanding 页面用于解释对应成功准则。本文记录来源与本项目的应用建议，不代表实现已完成、测试已通过或已取得 WCAG 合规结论。

## 1. Red Blob Games：Introduction to the A\* Algorithm

来源：[Introduction to the A\* Algorithm](https://www.redblobgames.com/pathfinding/a-star/introduction.html)

阅读范围：Frontier、Early exit、Movement costs、Heuristic search、The A\* algorithm。

**原文提供的依据**

- 搜索从 frontier 取出节点，再考察邻居；frontier 是搜索尚待处理的边界。
- 移动成本不同时，更新 `new_cost = cost_so_far[current] + graph.cost(current, next)`；发现更低成本时更新已有记录。
- 终点在出队时触发提前结束。文章明确指出，加权移动时首次把终点加入队列就停止可能得不到最优结果。
- 四向网格可使用 Manhattan 距离。A\* 在启发式不高估剩余真实成本时可找到最优路径。

**在本项目中的应用建议**

地图保持四向移动；地形给出正的进入成本。令 `c_min` 是所有可通行移动成本的下界，采用 `h(n) = c_min × Manhattan(n, goal)`。若所有可通行成本至少为 1，直接使用 Manhattan 即可。每次运行使用固定地图，两种算法共享相同成本与邻接规则。

这里的推导是：到终点至少需要 Manhattan 步，每一步成本至少为 `c_min`，因此该乘积不会高估真实成本。相邻格的 Manhattan 距离最多变化 1，故还满足一致性 `h(u) ≤ cost(u, v) + h(v)`。在这个模型下，正确执行松弛、队列排序和终点出队判断，可维持 A\* 的最优性。

加权后分别显示 **总代价** 与 **步数**：两种算法应得到相同的最优总代价，具体路径和步数可能不同。仅在全部移动成本为 1 时，总代价才等于步数。

**适用边界**

上述推导依赖四向相邻移动与非负成本下界。新增低于 1 的地形需缩小启发式尺度；允许零成本时可退回 `h = 0`；负成本、传送边或对角线移动需要重新设计算法或启发式。不要把地形加权实现为随意增加 `h` 的倍数。节点展开数反映本次搜索过程，不能替代运行性能测量，也不据此承诺 A\* 在所有图上展开更少节点。

## 2. Red Blob Games：Implementation of A\*

来源：[Implementation of A\*](https://www.redblobgames.com/pathfinding/a-star/implementation.html)

阅读范围：1.3.1–1.3.3、1.4、Algorithm、Vocabulary，以及网格存在等成本路径的说明。

**原文提供的依据**

- 示例 `cost(from_node, to_node)` 取目标格的权重，默认值为 1；这是作者选择的一种成本模型。
- 优先队列取最小优先级。发现更低 `cost_so_far` 后，更新成本、优先级和父节点。
- 简化堆实现允许同一节点出现多个队列条目，队列条目数因此不一定等于唯一待处理节点数。
- 术语对应为 `g = cost_so_far`、`h = heuristic`、`f = g + h`；frontier 对应 OPEN，reached 是 OPEN 与 CLOSED 的并集。
- 网格常存在等成本路径；返回形状不同的路径不意味着算法出错。

**在本项目中的应用建议**

起点 `g = 0`，路径成本累计进入后续格子的地形成本；起点自身不计入。显示以下量时均使用同一个搜索步骤的状态：

| 显示项   | 准确定义                                                         |
| -------- | ---------------------------------------------------------------- |
| Frontier | 已发现、仍待有效展开的唯一节点集合；不包含已从边界取出的 current |
| Current  | 此步从队列有效取出的节点；到达终点的那一步不必再展开其邻居       |
| g        | 从起点到该节点的当前已知最低成本；frontier 中节点的值还可能改善  |
| h        | 到终点的成本下界估计；不是实际剩余路径成本                       |
| f        | A\* 的排序值 `g + h`；不代表已找到该成本的完整路径               |

Dijkstra 按 `g` 排序。若沿用同一组数字面板，可将其有效启发式显示为 `h = 0`、`f = g`，并解释这一约定，避免显示 Manhattan 数值却暗示它参与了 Dijkstra 排序。

建议统一把一个动画步骤定义为：有效出队 → 检查终点 → 若未结束则松弛邻居 → 保存 current、frontier 与相关成本。回放必须读取该步保存的值，不能把搜索结束后的最终 `g` 倒填到早期画面。采用重复入堆策略时，过滤陈旧条目；frontier 计数取唯一有效节点集合。

**适用边界**

快照时点与视觉颜色是本项目的设计选择，并非原文规定。若将“取出终点”也计入展开数，应在指标中说明该计数约定；不能把失效堆条目的弹出次数混作有效展开节点数。本文只归纳算法思想，没有复制原文代码；原文代码另有其许可说明。

## 3. W3C：SC 2.5.8 Target Size (Minimum)

来源：[Understanding SC 2.5.8: Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

阅读范围：Success Criterion、Intent、Exceptions、Size requirement、Spacing。

**原文提供的依据**

- 指针目标原则上至少为 **24 × 24 CSS 像素**。小于该尺寸的目标可在满足指定间距或其他例外时符合此准则。
- 间距例外按目标中心的直径 24 CSS 像素圆判断，不能与其他目标或相邻小目标的圆相交；不是笼统要求每个按钮留 24 像素空隙。
- 同页存在符合尺寸要求的等效控件，是明确列出的例外。
- 注释 1：根据目标内部空间位置取值的控件，可视为一个目标，例如滑块、渐变取色器或可放置光标的编辑区域。
- 更大的目标通常更易使用；不能靠用户自行缩放页面才使默认目标达到要求。

**在本项目中的应用建议**

工具、播放、步进、帮助、分享等独立控件首先满足 24 × 24 CSS 像素；主要触屏控件可采用至少 44 × 44 作为本项目的易用性选择，避免将 44 写成 2.5.8 的最低标准。检查真实可点区域，包括透明 padding，而不只看图标大小。

35 列地图在手机上会很密集。提供放大的编辑视图，或同页大尺寸的方向控件与“应用当前工具”按钮，让用户无需精确点击小格子也能完成相同功能。

**适用边界**

不能仅凭每格不足 24 像素就断言整个空间编辑区域违反此条，也不能仅因使用一个 canvas/DOM 容器就自动视为合规。应按用户感知的交互目标、空间取值方式和实际等效操作评估。满足这一条也不证明整体可访问性。

## 4. W3C：SC 2.5.7 Dragging Movements

来源：[Understanding SC 2.5.7: Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

阅读范围：Success Criterion、Intent、Relationship to keyboard accessibility requirements、Examples。

**原文提供的依据**

- 使用拖动的功能，应有无需拖动的单指针操作方式，除非拖动本身必不可少或由用户代理提供。
- 键盘等效操作与无拖动单指针操作独立评估；只有方向键支持，不能自动满足本条。
- 点选起点后再点选终点、点击方向按钮、点击滑块轨道，都是页面列出的替代思路。
- 浏览器提供的原生滚动通常不属于本条；页面主动抑制原生滚动或自行实现滚动后，相关交互成为作者的责任。

**在本项目中的应用建议**

画墙、擦除与地形工具既支持连续绘制，也支持先选工具再逐格点按；起终点允许先选工具再点击目标格，不要求抓住标记拖动。键盘另保留可见焦点、方向移动、应用当前工具的操作路径。

手机默认保留页面滚动；如果连续绘图必须占用触摸手势，提供清晰的绘图模式，仅在画板内接管手势，并保留可退出的滚动路径。模式切换、`touch-action` 的具体设置及事件取消处理是工程建议，本文四个来源没有提供完整 Pointer Events 实现规范。

**适用边界**

此准则着重拖动替代，不等于完整覆盖自由绘制、路径手势、缩放或键盘可访问性的所有要求。是否能在真机上顺利滚动、停止绘制与精确点按，仍需实际交互验证，不能只依据 CSS 设置推断。

## 本轮应核验的结果

- 使用独立的最短路基准验证加权案例：两算法最优总代价相等，并覆盖“绕路更长但更便宜”、不可达、起终点相同等情形。
- 单步与重放核对同一步的 current、唯一 frontier 和 g/h/f，确认没有展示来自未来步骤的数据。
- 仅用点击/轻触完成编辑与起终点设置；仅用键盘也能完成操作；手机滚动与绘图模式互不意外干扰。
- 在目标视口测量独立控件的真实点击尺寸，并实际使用密集网格的替代编辑方式。

以上是待验证的验收建议，不是已通过结果。
